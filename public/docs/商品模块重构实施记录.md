### ① 单删留痕的锁后快照（`internal/module/product/service/product.go` 的 `Delete`）
旧写法在事务外读商品与变体、先构造 before 快照，:610 才进事务加锁 —— 校验与加锁之间别人改名 / 改价 / 回写成本价，审计记旧值而实际删掉的是新值。现在的顺序：事务外只做窄读归属（`GetRefFacts`，保住「不存在 / 别的工程」原来的 404）→ 事务内 `productWriteScopeTx`（工程 guard）→ `GetForUpdateTx`（父商品，显式工程谓词）→ `ListVariantsForUpdateTx`（该商品的变体稳定锁后读取）→ 组 before 快照 → `DeleteTx` → 集合键失效 → `recordChangesTx`。锁序与其它商品写操作一致（工程 → 父商品 → 变体）。

### ② 批删留痕的锁后快照（`internal/module/product/service/product_bulk.go` 的 `BulkDeleteProducts`）
`LockProductsTx` 只 Pluck id，够做「这批 id 还在不在」的集合校验，行本身与变体此前都是锁前读的，同一根因。现在：事务前只保留 `ListProductsByIDs` 取名称（仅用于整批拒绝时报出是哪几条，不进任何留痕快照）；事务内 `productWriteScopeTx` → `LockProductsTx`（全集校验，锁不到即整批拒绝，语义不变）→ **按同一升序逐条 `GetForUpdateTx` 取整行、逐条 `ListVariantsForUpdateTx` 取变体** → 组 inputs → `DeleteProductsTx` → 逐商品发失效 → `recordChangesTx`。不新增通用 Repository（曾试过两个批量 …ForUpdateTx 方法，按「不新增通用读法」撤掉，未留在代码里）。`GetForUpdateTx` 上那段「为什么不用 LockProductsTx」的注释同步更正为：那个只出 id，只够做集合校验。
