# 模块接口清单（实施状态）

> 本文档记录全部业务模块的实际接口、跨模块依赖契约和当前实施状态。
> 统一约定：只用 GET（查询）和 POST（增删改），禁止 RESTful 路径参数，全部用 Query 参数。

## 核心数据流

```
权限定义 → 菜单绑定 permission_code → 角色菜单(p) → 用户角色(g)
  → 用户直接额外权限(p) → /api/admin/routes → Casbin API 鉴权
  → 部门上下文 → datarule SQL/Omit/DTO 注入
```

## 1. 权限模块 `/api/permission/`

`sys_permission` 表 CRUD。权限定义 `permission_code → api_path + api_method` 的唯一数据源。

| 路由 | Method | 说明 |
|------|--------|------|
| `/api/permission/list` | GET | 权限列表（分页，支持 module/code/api_path/status 筛选） |
| `/api/permission/detail` | GET | 权限详情（query: id） |
| `/api/permission/options` | GET | 启用权限选项（菜单表单使用，不分页，支持 module 筛选） |
| `/api/permission/create` | POST | 新建权限，method 仅 GET/POST |
| `/api/permission/update` | POST | 更新权限（已授权时同步更新 Casbin 对应 p 策略的 path/method） |
| `/api/permission/delete` | POST | 批量删除（被有效菜单引用时拒绝） |

前端页面：`web/src/views/permission/` — 列表页 + CRUD 弹窗

---

## 2. 菜单模块 `/api/menu/`

`sys_menus` 树形 CRUD。type=2,3 必须绑定启用的 `permission_code`；type=1,4,5 不得绑定。

| 路由 | Method | 说明 |
|------|--------|------|
| `/api/menu/tree` | GET | 完整业务树（支持 status/type/search 筛选），供角色/管理员分配界面展示 |
| `/api/menu/detail` | GET | 菜单详情（query: id） |
| `/api/menu/create` | POST | 新建菜单（type/parent_id/title/permission_code/icon/path/component/sort_order 等） |
| `/api/menu/update` | POST | 更新菜单（禁止父子环；系统菜单受保护） |
| `/api/menu/delete` | POST | 批量删除（有子节点、系统菜单或仍被 Casbin 引用时拒绝） |

前端页面：`web/src/views/menu/` — 树形表格 + form 弹窗

---

## 3. 角色模块 `/api/role/`

`sys_role` 元信息 CRUD。角色菜单和角色用户关系分别写 Casbin p/g 策略，不新增关系表。
角色状态通过 Casbin `g2` 激活关系控制。

| 路由 | Method | 说明 |
|------|--------|------|
| `/api/role/list` | GET | 角色列表 |
| `/api/role/detail` | GET | 角色详情（query: id） |
| `/api/role/create` | POST | 创建角色（role_code/role_name/status/sort_order） |
| `/api/role/update` | POST | 更新角色元信息 |
| `/api/role/delete` | POST | 删除角色（事务清理 sys_role + Casbin p/g/g2 策略 + LoadPolicy） |
| `/api/role/menu/list` | GET | 角色直接拥有的 menu_id 列表（query: role_id） |
| `/api/role/menu/save` | POST | 全量替换角色权限（role_id + menu_ids → 收集 code → 写 Casbin p → LoadPolicy） |
| `/api/role/user/list` | GET | 角色下的用户列表（query: role_id） |
| `/api/role/user/save` | POST | 全量替换角色用户绑定（role_id + user_ids → 写 Casbin g → LoadPolicy） |

前端页面：`web/src/views/role/` — 角色 CRUD + 菜单授权 + 用户分配三个面板

## 5. 部门模块 `/api/dept/`

## 跨模块依赖契约

### 依赖关系

```
                    ┌──────────────┐
          ┌────────→│ permission   │  ListByCodes(codes) → []PermissionBrief
          │         └──────────────┘
          │
┌─────────┐  ┌──────┐
│  role   │─→│ menu │  GetPermissionCodesByIDs(ids) → codes[]
└────┬────┘  └──────┘  GetIDsByPermissionCodes(codes) → ids[]
     │                  BuildAuthorizedTree(codes) → MenuNode[]
     │
     └──────────────────────┐
                            │
                     ┌──────▼──────┐
                     │    admin    │  ListByDeptID → []AdminBrief
        ┌────────────┤             │  BatchSetDeptID(userIDs, deptID)
        │            └──────┬──────┘  CountByDeptID → count
        │                   │
  ┌─────▼──────┐      ┌────▼──────┐
  │  dept      │      │  role     │  GetRoleCodesByUserID(userID) → codes[]
  │ (admin     │      │ contract  │  GetIDsByCodes(codes) → ids[]
  │  contract) │      └───────────┘
  └────────────┘
```

### Casbin facade（pkg/casbin）

集中式策略变更函数，业务模块不得直接散落调用 LoadPolicy：

| 函数 | 说明 |
|------|------|
| `ReloadPolicy()` | 重载内存策略 + 重建 URL→code 映射 |
| `ReplaceRolePermissions(roleCode, policies)` | 全量替换角色 p 策略 |
| `ReplaceUserRoleBindings(userID, codes)` | 全量替换用户 g 策略 |
| `ReplaceRoleUsers(roleCode, uids)` | 全量替换角色 g 策略 |
| `ReplaceUserPermissions(userID, policies)` | 全量替换用户直接 p 策略 |
| `ActivateRole/DeactivateRole(code)` | 启用/禁用角色（操作 g2） |
| `DeleteRoleAllPolicies(code)` | 删除角色全部 p/g/g2 |
| `GetRoleCodesByUserID/GetUserIDsByRoleCode` | 查询用户↔角色关系 |
| `GetRolePermissions/GetUserDirectPermissions` | 查询权限列表 |

### DataRule 引擎（pkg/datarule）

| 组件 | 说明 |
|------|------|
| `RuleProvider` 接口 | datarule 模块实现，在 SetupRoutes 时注入引擎 |
| `RegisterDomain(DomainConfig)` | 注册数据域的字段白名单 |
| `RegisterPlugin(db)` | 注册 GORM BeforeQuery 回调 |
| GORM 回调行为 | 缺用户上下文放行；命中 domain 但缺身份 fail-closed；Omit 双防线 |

## 安全约定

- **Omit 两层防线**：datarule 插件自动 Omit + 业务 DTO 映射阶段删除响应键
- **缺身份拒绝**：命中已注册 domain 但取不到 user_id 时 fail-closed
- **domain/field/operator 白名单**：只能从 schema API 返回的列表中选择
- **Casbin LoadPolicy 刷新**：所有 p/g/g2 变更通过 facade 封装，自动刷新
- **删除校验**：菜单/部门/角色删除时检查子节点和引用关系
- **角色启停**：禁用不删除 p/g，启用时立即恢复
