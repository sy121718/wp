## 0. 本批要解决的四件事

方案 §17 给 B1 的判据是「契约有唯一所有者；没有万能 DSL；接口示例经审查」。落到四问：

| # | 问题 | 本文档的答案 |
|---|---|---|
| 1 | 动作目标长什么样、谁校验 | §2（`core.ActionTarget` 联合类型，唯一所有者 = `internal/builder/core`） |
| 2 | 版本与并发怎么表达 | §3（`expectedVersion` 走 dto，`schemaVersion` 走文档根） |
| 3 | 前端怎么拿到动态结果并就地更新 | §4（write-base 新增一个分发入口，不是第二套基座） |
| 4 | 访客 CSRF 从哪来 | §5（服务端渲染片段时注入，静态产物不含 token） |

## 1. 不做什么（先划掉，避免边做边扩）

- **不新增文档格式**。区块配置仍是 `blocks.document`（`jsonb`），页面仍是同一份 Document 协议；
  本批只在既有协议上加**受控字段**，不引入平行的 `business_block` 文档。
- **不新增组件注册机制**。`core.Register` + `Component`（`Type()` / `Validate()`）+ 六个 Provider
  已经够用（B0 台账 §9.1 有逐项证据）。
- **不做通用动作引擎**。动作是**封闭联合类型**，不是表达式、不是 URL 模板、不是脚本。
- **不在 `Props` 自由 JSON 里藏动作**。见 §2 的理由。

## 2. 动作目标：`core.ActionTarget` 联合类型

### 2.1 为什么不能直接塞进 `Props`

`core.Node.Props` 是 `json.RawMessage`，任何组件都能往里写任意键 —— **实测**：
`productlist/jet.go` 的「查看全部」现在就是从一个自由属性里读目标，`cardstack` 同理。
散在 `Props` 里的后果是「合法动作」没有单一校验点：控制器校验一遍、AI/MCP 入口校验一遍、
检查器禁用按钮再来一遍，三份判据必然漂移（方案 §8.2 正是要求三个入口执行同一份校验）。

所以动作提到 `Node` 的**结构层**由 `core` 校验，不进 `Props`。

### 2.2 形状（定稿）

```jsonc
// Node 新增一个可选字段 actions；键是组件声明的动作名（如 "viewAll" / "checkout"）
"actions": {
  "viewAll": { "kind": "page",         "pageId": "uuid" },
  "checkout": { "kind": "local",        "partKey": "checkout" },
  "detail":   { "kind": "presentation", "instanceId": "uuid" },
  "docs":     { "kind": "external",     "url": "https://…", "newTab": true }
}
```

四档 `kind`，**每档字段互斥**（定稿判据：未知 `kind` 一律拒绝，不做「忽略未知字段继续跑」）：

| kind | 必填 | 语义 | 谁解析 |
|---|---|---|---|
| `page` | `pageId` | 导航到本工程某 Page | 控制面校验归属 + 发布状态；构建期按语言解析 URL |
| `presentation` | `instanceId` | 导航到某 PresentationInstance | 同上 |
| `local` | `partKey` | 同组件内切步骤/展开部位 | 组件自己（`partKey` 必须在自己声明的 parts 里） |
| `external` | `url` | 普通内容外链 | 构建期校验协议白名单（http/https）；**敏感流程禁用** |

### 2.3 拒绝规则（可判定，不是形容词）

1. 未知 `kind`、缺必填字段、多余字段 → 拒绝（配置可存草稿，发布必报错）。
2. `pageId` / `instanceId` 必须是**本工程**的、且存在；跨工程引用拒绝。
3. `local.partKey` 必须是该组件 `Parts()` 声明过的值；不允许 CSS selector。
4. `external.url` 只允许 `http`/`https`；且**登录 / 付款 / 找回 / 重置四类动作禁用它**
   （方案 §10.1 第 5 条：敏感流程不接受任意外域回跳）。
5. 必需动作（组件声明的 `RequiredActions()`）缺失或目标未发布 → **阻止发布**，不静默隐藏按钮。

### 2.4 与 `partKey` 的边界

`partKey` 是**组件内部区域名**，不是全站页面槽位。它由组件通过新接口声明：

```go
// core.PartsProvider（新增，可选）
type PartsProvider interface {
    // Parts 返回可被 local 动作引用的内部区域名。
    Parts() []string
}
```

未声明 `Parts()` 的组件不能使用 `kind: "local"`（校验时直接拒），这挡住「给任意组件塞
一个指向别人的 partKey」。

### 2.5 实测证据（写这份定稿前查的）

- `core.Node` 字段：`ID` / `Type` / `Props` / `Children` + 编辑期 `Name`/`Hidden`/`Locked`
  —— 加一个 `Actions` 字段即可，不动既有语义。
- `productlist/jet.go` 的「查看全部」读的是槽位（不是自由属性）；`cardstack.go` 同样读槽位。
  这两处是 B5 的替换点：槽位 → `actions.viewAll`。
- 现有 `Provider` 六个（`PropsSpec` / `Palette` / `Translatable` / `AlignedRepeater` /
  `FieldBinding` / `CollectionSource`），**没有一个**表达「动作」—— 所以这是真缺口，不是重复造。

## 3. 版本：两个版本，别混

| 版本 | 位置 | 变化影响 | 拒绝方式 |
|---|---|---|---|
| **配置协议版本** `schemaVersion` | 区块 Document 根 | 影响能力契约（字段含义变了） | 未知版本**明确拒绝**（不猜、不降级渲染） |
| **并发版本** `expectedVersion` | 保存请求 dto | 不影响文档内容，只防丢更新 | 不匹配 → **409**，带当前版本号 |

### 3.1 为什么必须两分

- 把 `schemaVersion` 拿来当并发控制会有一个致命问题：改一次配置协议就要全库文档涨一版，
  所有编辑器同时开始报冲突。
- 反过来，用 `expectedVersion` 表达「这份配置是第几代协议」则无法区分「同一个 v1 文档的两次编辑」
  与「一次协议升级」。

### 3.2 `blocks` 表的缺口（B0 已实测）

```
\d blocks → 只有 project_id / name / kind / document / create_time / update_time /
            category / reuse_mode / id
```

**没有 `version`，没有快照，没有预设来源。** 所以 B2 的第一步是加列，而不是改服务：

| 迁移动作 | 判据 |
|---|---|
| `blocks` 加 `version bigint not null default 1` | 并发控制基准；`expectedVersion` 比对它 |
| 加 `preset_key` / `preset_version`（可空） | 追溯「这份区块是从哪个预设复制来的」 |
| 不可变快照表（是否独立表在 B2 定稿） | 编译期锁定版本用；至少能回答「上个月发布时用的是哪份文档」 |

### 3.3 编译期锁定

判据（方案 §12）：**编译期间不能再次读取可变最新文档**。落地方式：编译输入里携带
`(blockId, version, documentSnapshot)`，编译中途的编辑不影响本次产物。

## 4. 前端结果分发：在原基座加一个入口

### 4.1 实测：现在没有这个入口

`write-base.js` 的成功路径只有一个收尾函数 `afterSuccess(form, submitter, data, text)`（:553-572），
它做四件事：toast → 关抽屉 → `data-write-nav` 导航 → `data-write-reload` 刷新。

`data-write-outcome` 只对 `mode === 'bulk'` 生效（:649），普通写动作没有「就地更新」这条路。
所以业务区块「加购成功后只更新角标和金额」目前**无处可挂**。

### 4.2 定稿：`registerResultHandler`

在 `write-base.js` 内新增一个注册表，与既有的 `registerPayloadBuilder`（:719）同形：

```js
// 组件侧注册（每个组件一次，不是每个实例一次）
WBUI.writeBase.registerResultHandler('commerce.cartCheckout', function (ctx) {
  // ctx = { form, submitter, data, payload, text, instanceId }
  // 返回 true 表示"我处理了"，基座不再执行默认导航/刷新
});
```

### 4.3 约束（每条都有对应判据）

1. **仍是同一个基座**：只加一个注册表 + 一处调用点，不新增第二套 fetch/submit 监听。
2. **按能力名分发，不按页面或实例**：`data-write-handler="commerce.cartCheckout"` 声明在表单上；
   没有该属性时行为完全不变（现有 52 个表单零影响）。
3. **只提交一次**：注册表是「同一 key 覆盖」语义，重复初始化不会重复绑定。
4. **失败不吞**：handler 只在成功路径被调用；失败路径继续走既有 `setStatus` + 保留输入。
5. **会话过期**：JSON 401 必须走受控登录态，不允许接收 HTML 登录页后当成功（§5 配套）。
6. **默认不刷新整页**：返回 `true` 即由 handler 负责局部更新；返回 `false`/`undefined` 走原逻辑。

### 4.4 一个未被现有测试覆盖的风险

`finishOk` 里 `data-write-reload` 会 `location.reload()`（:674-677）。业务区块就地更新时**不能**
带这个属性，否则 handler 即使处理了也会被刷掉。定稿：`data-write-reload` 与
`data-write-handler` 同时出现 → 基座报错（配置互斥），而不是「谁先谁赢」。

## 5. 访客 CSRF：token 由服务端渲染时注入，绝不进静态产物

### 5.1 实测现状

| 事实 | 位置 |
|---|---|
| 访客域 token 由中间件挂到 context | `runtimefragment/endpoint.go:103-110`（`VisitorCSRFContextKey`） |
| token 由**片段渲染**带进表单隐藏域 | `user_forms.go:51`、`user_account_forms.go:74`、`comment.go:89` |
| 后台侧的 token 走 `<meta name="csrf-token">` | `write-base.js:513-514`；模板如 `admin/page/page_redirects.html:33` |
| 访客页面是**静态产物**，不能烘焙 token | 不变量 1 第一档 + 产物确定性（不变量 5） |

### 5.2 定稿结论

1. **访客业务区块不读 `<meta name="csrf-token">`**：那份 token 来自后台页壳，访客页没有；
   即便有，烘焙进静态产物也会违反确定性构建（同一输入必须产生相同字节）。
2. **token 的获取路径**：区块初始化时先取一个公开 JSON 端点（如 `GET /api/<域>/csrf`）拿 token，
   或由首次业务请求的响应头下发。**具体取哪条在 B4 定稿**，但两条硬约束现在就能定：
   - 不得要求静态产物里预置 token；
   - 不得因为「后台基座有这个 meta」就假定访客也有。
3. **无 JS 时的降级**：按既有 `data-requires-js` 模式禁用提交并给提示，不自动回退到固定业务页
   （方案 §4.3 第 13 条）。

## 6. 唯一所有者清单（冲突时按这张表判）

| 契约 | 唯一所有者 | 不允许的第二处 |
|---|---|---|
| 动作目标联合类型与校验 | `internal/builder/core`（`ActionTarget` + `Validate`） | 页面域/控制器各自校验一遍 |
| 组件可编辑属性 | `core.SpecProvider` | 模板里的隐式约定 |
| 组件内部 parts | `core.PartsProvider` | CSS selector / 约定类名 |
| 区块版本与并发 | `internal/module/block`（dto + service + model） | 页面域顺手改 blocks 表 |
| 页面/实例地址解析 | `internal/module/presentation`（`PublishedEntityLocator`）+ publication 的寻址 | 组件里拼语言前缀 |
| 前端写通道与结果分发 | `internal/templates/static/js/ui/write-base.js` | 组件自带 fetch |
| 访客 CSRF | `internal/module/user` 的访客会话契约 | 组件自己生成 token |
