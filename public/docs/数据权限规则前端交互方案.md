# 数据权限规则前端交互设计方案（实施状态）

更新时间：2026-07-16

> 本文档记录最终实施状态。标记 ✅ 的表示已实现并可用，⚠️ 表示与原始方案有偏差。

关联文档：[权限管理开发方案.md](./权限管理开发方案.md)

---

## 一、设计目标 ✅

管理员在后台创建数据权限规则时，通过可视化界面选择域、字段、操作符、值，用 AND/OR 组合条件，同时可勾选字段屏蔽。前端全程只看到中文 label，不接触真实数据库字段名。

实际实现：`web/src/views/datarule/` 规则编辑器，支持上述全部交互 ✅

---

## ⚠️ 二、核心原则（有偏差）

| 原则 | 方案设计 | 实际实现 |
|------|---------|---------|
| 前端只看 label，不碰 field | 前端展示 label，提交 field | ✅ 一致 |
| domain 标识 | sys_rule.domain 填业务域 | ✅ 一致 |
| 字段动态获取 | 从 INFORMATION_SCHEMA 实时查 | ⚠️ 改为 `pkg/datarule.RegisterDomain` 代码注册，不从 INFORMATION_SCHEMA 查 |
| 映射放 enums | label ↔ field 映射放 enums | ⚠️ 改为 `pkg/datarule.DomainConfig.WhiteList` 代码注册 |

## 三、数据流 ✅

### 3.1 查字段给前端选（已实现 ✅）

```
前端：GET /api/datarule/schema/list → 已注册 domain
前端：GET /api/datarule/schema/detail?domain=ADMIN → 字段白名单

⚠️ 路由方案设计为 `/api/datarule/schema` 和 `/api/datarule/schema?domain=`，
实际使用 `/api/datarule/schema/list` 和 `/api/datarule/schema/detail?domain=`
```

返回结构：与方案一致，返回 `{ domain, table, columns: [{ field, label, data_type, operators }] }` ✅

### 3.2 提交规则（已实现 ✅）

前端提交的 config 为 JSON 字符串，存入 sys_rule.config 字段。结构与方案一致。

### 3.3 分配规则（已实现 ✅）

规则保存后可独立分配给角色、用户或部门。部门分配支持“仅本部门”和“本部门及全部下级”；同一用户从多个主体命中的规则全部作为限制生效，行条件为 AND，屏蔽字段取并集。

### 3.4 回显规则（已实现 ✅）

查询 → 返回 config JSON 字符串 → 前端解析回填 editor

## ⚠️ 四、字段映射管理（方案设计与实际不同）

方案设计 `enums/datarule_enums.go` 中维护 `FieldLabels/DomainTables` 映射表。

实际实现：
- 字段白名单在 `datarule_router.go` 初始化时通过 `pkg/datarule.RegisterDomain()` 注册
- label + field + operators 直接在注册代码中定义
- 首期只注册 `ADMIN → sys_admin` 一个域

**后续扩展：** 新增域时在 `SetupDataRuleRoutes` 中追加 `RegisterDomain` 调用即可。

## 五、前端交互界面（已实现 ✅）

规则分配弹窗提供角色、用户和部门选择；部门使用树形选择，并为每个已选部门单独配置继承范围。

`web/src/views/datarule/components/createForm.vue` 实现了完整的规则编辑器：

```
新建/编辑数据规则

  规则名称: [input]
  数据域: [select ▼]
  状态: [启用/禁用]
  备注: [input]

  ┌─ 字段屏蔽 ──────────────────────────────┐
  │  ☑ username（用户名）                     │
  │  ☑ email（邮箱）                          │
  │  ☐ phone（手机号）                        │
  └─────────────────────────────────────────┘

  ┌─ 条件组 ───────────────────────────────────┐
  │  组 1 [AND ▼]                              │
  │    字段 [username ▼]  操作 [LIKE ▼]  值 [%admin%]  [删除] │
  │    字段 [status  ▼]  操作 [IN   ▼]  值 [1,2]          [删除] │
  │  [+ 添加条件]                               │
  │                                             │
  │  [+ 添加条件组]                              │
  └─────────────────────────────────────────────┘
```

- 操作符随字段类型过滤（通过 operators 白名单）✅
- 值支持 `dept.scope:SELF` 等引用 ⚠️ 引擎端已支持，前端未做特殊输入处理
- 每组可选 AND/OR，组之间 AND 连接 ✅
