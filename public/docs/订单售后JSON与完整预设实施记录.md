## 本批结果

- 访客入口为 `/api/site/orders`，提供列表、详情、可退事实、售后进度和退货申请。身份仅取访客会话，不接受客户端 userId 或后台 cookie。写入保留访客 CSRF；私有事实不可缓存。
- 金额保留整数分，时刻保留 unix 毫秒。详情和申请回执不复用后台响应形状，不发送 HTML、展示 Label、成本、后台备注或支付流水。
- 可申请退货由订单服务的同一状态口径与当前可退额度提供。重复 requestId 须属于同一访客、同一订单、同一申请内容；不同内容返回 409。
- 完整“订单与售后”区块内部包含列表、详情、申请和结果。具名写结果使用 `commerce.orders`；同页多个实例共享业务事实刷新，展开状态和失败输入各自保留。
- 权威预设 `commerce.orders@1` 包含账号中心和订单区块。订单的登录入口显式指向该账号实例；认证完成保留账号自身 account 能力，通过已有会话事实通知刷新订单。认证事实重复事件不会重复刷新，且不强行切换其它实例步骤。
- 删除旧 `ordersList`、`orderDetail`、`returnRequest` HTML 能力、三个模板、对应装配依赖及旧订单片段样式，避免双轨。
- 加购检查器正常说明收为灰色“自动加入当前商品”，仅旧配置与缺当前商品上下文使用警告。
