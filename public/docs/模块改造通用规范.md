# 模块改造通用规范（自商品四轮与发布恢复提炼）

> 来源：`public/docs/商品模块架构重构执行记录.md`、`商品模块MVC改造执行记录.md`、
> `商品模块重构实施记录.md`（346 行，含七轮续批）、`商品模块业务裁决-DEC.md`、
> `SEO导航发布恢复重构执行记录.md`。
> 定位：本文件是**方法的唯一规范源**；每个模块另写一份任务书（`模块改造任务书-<模块>.md`），
> 只填该模块的事实与批次，不重述方法。判据（谁能做什么）仍以 `AGENTS.md` 分层表为唯一权威，
> 本文件不新增判据，只固化「怎么按判据改」。

## 1 六个阶段（顺序不可跳）

1. **画像**：用可复现的统计拿事实（文件数、`PageResp`/`ListResp` 命中、`gin.H`、
   模块内 `pageview.`/`adminui.`、手写 `Offset(`、service 里的界面 key、dto 里的展示字段）。
   统计只作筛查起点，结论前回读语义 —— 计数不是判据。
2. **任务书**：写死目标、层归属表、批次、每批判据与断言、DEC 待决、验证矩阵、禁止项。
3. **层归属表先行**：每一处改动先回答「属于哪层、该层允许什么、禁止什么」。判据不齐不动代码。
4. **分批实施**：一屏/一域一批；先删旧形状再建新形状；每批只放该批改动。
5. **集中验证**：编辑侧全部完成后由唯一验证者集中跑（见 §10）。
6. **收口**：反查过期注释、重复实现、形状漂移；门禁台账只减不增；提交并写执行记录。

## 2 层归属表的固定形状

每行四列：`改动域 | 层 | 本批允许 | 本批移除的越界职责`。范例（商品 B0）：

| 改动域 | 层 | 本批允许 | 本批移除的越界职责 |
|---|---|---|---|
| 列表读取与投影 | service / model | 一次读取事实、批量装配、复用夹页工具 | 逐行详情查询、整行读 |
| 页面入口 | inbound/http | binding → 调 service → 成功渲染 / 失败 JSON | 派生展示数据、拼 HTML、自选错误状态 |
| 模板 | templates | 结构、文案、选中态、表单初值 | 业务计算、金额求和、状态机第二份实现 |

## 3 八类越界判据（本仓实际出现过）

1. **展示字段进 dto**：`Label`/`Title`/`Tone`/`Badge`/`ErrorText`/`StatusText` 这类
   「换语言要重算或换样式要重算」的成品串 → 前端派生；dto 只留语言无关事实。
   例外：字段名带 Label 但语义是业务值（如 `order_attr_resp.go:89` 的 `Title` 是属性名）。
2. **`*PageResp`**：一屏一个页面响应类型 → 页面用「现成数据对象」组合（`pageview.Objects`），
   JSON 用 `{code,message,data}` 的业务 DTO。
3. **`gin.H` 出口**：页面 GET 成功一律 handler 声明模板由统一渲染器渲染；`gin.H` 只允许出现在
   纯 JSON 出口（且优先真实 DTO）。
4. **模块内 `adminui.`/`pageview.`**：pageview 只能在 handler（inbound）出现；service/model/contract
   不得 import 渲染出口。
5. **页面 POST 写响应**：写一律 JSON；导航由前端 `data-write-nav` 决定，后端不发 302/HX-Redirect。
6. **错误键自造**：service 里出现 `"admin." / "shell." / "user." / "workbench."` 字面量 → 界面 key
   归模板 t/tf；业务错误在 enums 声明处 `key + 中文兜底 + 状态码`，service 只交事实。
7. **跨模块直表/直 dto**：读别人的表或 import 别人的 dto → 走 contract；契约包不得反向 import
   builder/core 之外的实现层。
8. **整行读与手写分页**：`Select("*")` 后只用两三列、或 `Offset(` 手写在 model 里而 service
   另有页码语义 → 窄投影 + `pkg/pagination` 统一夹页与唯一尾键。

## 4 事务与锁（发布/金额/归属类模块的重点）

- 一次用户可感知的写涉及两处以上持久化 → 同一事务；事务边界在 service，句柄下传 `…Tx`。
- 读-改-写必须行锁或原子 SQL；审计 `before` 必须是**锁后**快照，不是请求前的旧读。
- 锁序固定并写进注释：如商品「工程协调锁 → 商品行 → 变体行」；菜单「工程 → 标签 → 商品 → 变体」。
- 顾问锁键必须规范化（`uuid.Parse(...).String()`），否则大小写别名分裂键、二次取锁反序。
- **事务回调内禁止调用自开事务的 model 方法**（自锁挂死；正确形状是先加 `…Tx` 变体）。
- 多路径收敛必须有终止条件：本批键与上批相同即停（否则 pending 批次无限重放）。
- 批量全成全败；拒绝时把 id/名称/原因放进 `data.items`。
- `keepPending` 类调用是**终端动作**，之后不得再无条件结案。

## 5 读取与分页

- count 与 list 必须同过滤条件；「先取全量再内存分页」只允许出现在无法下推的合并过滤，
  且必须在任务书里写明理由与规模边界。
- 分页必须有**唯一尾键**（`id ASC`），否则同 sort/同时间的行会跨页漂移。
- 越界页码：普通态夹到有效末页；偏移乘法用饱和（`pkg/utils/paging.go`），不回绕成首页。
- 窄投影：只取消费列；批量读取替代逐行查询；列表不因附属读取故障整体失败，但故障事实要如实显示
  （不许把故障显示成 0/空）。
- 规模结论必须有计划证据（EXPLAIN + 真实行数），小样本不证明生产慢；不凭小样本加索引。

## 6 错误与文案

- 一条错误在声明处定义一次（key + 中文兜底 + 状态码）；出口只调 `response.ErrorStatusAuto`。
- 明细错误键分域（如 `product.err.*`）：新键迁移要复制旧 seed 的全部语言与运营值，
  保留旧键兼容历史种子，缺词补中英兜底，SQL 先 PREPARE 校验。
- 界面文案域：`admin. / shell. / user. / workbench. / site. / msg_`；错误 key（`*.err.*`）不得当界面文案。
- 语言不进全局可变上下文；模板取词走请求级 t/tf，模板语言不能塞进全局 Jet Set（竞态）。

## 7 页面出口

- 页面 GET 成功：handler 声明模板 + 统一渲染器（`pkg/view`），语言与公共上下文由渲染器注入。
- 页面 GET 失败、API 失败：JSON `{code,message,data}` + 真实状态码。
- 401/403 一律 JSON，不因 `Accept` 或 `HX-Request` 改成跳转（`internal/middleware/builtin/auth.go` 注释即契约）。
- 空态与徽标走唯一片段（`partials/empty_state.html`、`partials/badge.html`），手写次数受门禁预算约束。

## 8 测试

- 先红后绿：缺陷类改动必须先写能复现的断言。
- 断言等式而非各自的值；错误断言状态码 + 对外文案且不含内部原文；页面断言真实 HTML 片段。
- 表结构一律来自生产迁移（`support.NewMigratedPGTestDB`）；列名必须查 `information_schema` 实测，
  `init_builder_schema.sql` 有多列已被后续迁移改名/删除。
- 注入点必须命中**生产实际入口**（如发布走 `ActivateTx` 而不是 `Activate`），否则是假绿。
- 收敛/恢复类用例按**回执 id** 断言，不用总数等式（收敛是全表领取）。
- 「整批一个事务」的后果要写进测试：失败后账本 0 行、产物一并回滚；要造部分状态必须显式构造。
- 契约变更（如 401/403 形态）改测试断言，不改回旧实现。

## 9 编辑代理纪律

- 唯一编辑代理**只编辑**：不跑 build/test/vet/门禁/数据库测量，不做 benchmark，不提交不合并。
- 主代理是唯一验证者；红绿、日志、验收由主代理集中执行。
- 小步派发：一次一个可独立验收的批次；brief 过大会整轮失败（本仓实测）。
- 待决业务口径登记到模块 DEC 文档，**不擅自决定**，也不因此停住其余明确实现。

## 10 验证矩阵与预算

| 阶段 | 命令 | 预算 |
|---|---|---|
| 每批 | `go build ./...` + 受影响包与 feature | 分钟级 |
| 每批 | `bash scripts/check-all.sh`（30 脚本） | 分钟级 |
| 每批 | `git diff --check` + `code-review-graph update` | 秒级 |
| 合 main 前 | `go test ./internal/... ./pkg/...` 与 `go test ./public/...` 各一次 | internal+pkg ≈ 690s、public ≈ 3151s |

禁止默认全量；报红先到 main 复跑同一条用例做归属判断，main 自带红不算本批引入、也不顺手改。

## 11 门禁与台账

- 门禁预算只减不增；豁免必须写理由并被测试断言。
- Go 门禁按**出现次数**计数，`grep -c` 按行统计会少算 —— 复算用 `strings.Count` 口径。
- 修复导致的登记调整（如语句上限、裸 SQL 处数、空态/徽标预算）必须在提交说明里给出判据。

## 12 交付与提交

- 一个模块一个分支一个工作树（`.worktrees/<模块>-refactor`），基线写明提交 hash。
- 提交按层分批、中文说明、精确暂存（逐文件 `git add`）；文档与代码分开提交。
- 台账（执行记录）只记**已验证**的事实：命令、退出码、日志路径、失败归属；不把局部修复称为整体完成。
- 不自动合并 main、不 `amend`、不 `reset --hard`；主区的未跟踪资料不动。

## 13 反模式清单（出现即判失败）

1. 把 `*PageResp` 改名成 `*Resp`、把展示代码从 controller 搬到 service、另建 Go 展示包 —— 都不是重构。
2. 为通过门禁加豁免、为变绿删用例/放宽断言、手抄 `CREATE TABLE`。
3. 用 `grep -c` 冒充门禁计数、用工具通过数量摘要冒充穷举用例。
4. 在事务回调里自开事务、在持锁窗口内做 FS/网络 IO 后再判库、锁键不规范。
5. 用「本该如此」解释失败；结论里出现「某库做不到」而没有文档路径或样例输出。
