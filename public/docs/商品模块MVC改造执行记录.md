## 完成与验收

本轮实施与集中自动化验收已完成。以下记录实际变更与证据，不能据此推断其他模块也已改完。

### 实际交付

1. 商品、分类、品牌 SEO 评分迁到三条独立 JSON API；删除旧 HTML 评分、远程 SEO 抽屉、DOM TargetID/隐藏字段/评分视图对象。共享 scoring 算法保留，商品不再依赖 scoreview。页型、维度权重、等级、颜色、建议、重复项和覆盖范围由前端展示。
2. 父分类搜索返回对象；标签命中复用分页 JSON，列表与总数来自同一个结果，删除旧 HTML/OOB 路由与模板。变体预览迁到 `/api/product/variant/preview`，JSON 与 FormData 绑定行为保持一致。
3. 详情模板校验与预览编排进入 service；依赖放在处理器实例，移除包级可变依赖。编辑预览优先使用当前绑定实例；复制来源严格按工程读取。成功传递构建字节，失败返回真实状态 JSON。
4. 共享认证与页面拒绝统一 JSON、真实状态及 no-store，不再根据 Accept/HX 返回提示页或跳转。写基座拒绝服务端重定向；导航、刷新由前端显式声明。
5. 预览缩略、放大和新窗口采用仅 `allow-scripts` 的 iframe 沙箱，不开放同源权限；相对资源使用文档 base，订单模拟控件同步适配。网络/JSON 解析故障使用界面失败文案；弹窗被拦截可见提示。
6. 分类、品牌的保存按钮保持默认提交，按 Enter 不再误触 SEO。旧请求不会覆盖新搜索，失败保留输入，标签空页不出现错误的分页区间。
7. SEO 商品索引逐批完整读取；商品列表以 `id ASC` 结束排序，205 条同时间/同 sort 数据仍能完整覆盖。是否已发布依据实际 Publication 的 ActivePath/ArtifactHash，拟定 URL 或状态镜像不足以获得 canonical/schema 技术分。
8. 译文存储不可用、读取失败、写入失败向统一出口传播；读取失败停止写入，不再假定所有内容变化后继续保存，也不把内部故障当作表单 400。
9. 清除旧展示映射、未引用的界面常量、旧提示页/跳转测试 helper 与过期注释。保留跨模块实际引用的商品实体名称 key、原始业务 Title/Label、发布 URL 迁址 WithRedirect 语义。

- 205 条商品具有相同 sort/create_time，并按逆序 ID 插入；分页遍历与 SEO 索引 ID 集合均等于完整升序 ID 集，无遗漏/重复。
