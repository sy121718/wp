# 权限体系缺口与回归记录

> 审核基线：提交 `652521f`，当前根图谱、运行源码及 `public/docs`。
> 状态说明：`待修复`、`修复中`、`待回归`、`已完成`、`后续规划`。

## 审核结论

现有代码已具备菜单、权限点、角色、部门、数据规则和 Casbin 基础结构，但提交时尚未形成可验证的端到端权限闭环。设计文档中的“已实现并可用”不能作为运行证据，以下问题以当前运行源码为准逐项闭环。

当前发现的权限业务逻辑缺陷和硬伤均已完成代码修复，未标记“已完成”的项目主要缺少真实 HTTP 或浏览器回归证据。具体业务数据域接入不作为当前权限体系硬伤：数据规则引擎保留为基础能力，后续由管理员在页面基于后端注册的数据域、字段白名单和运算符组合规则，不允许页面提交任意 SQL。

## 验收原则

1. 受控 API 必须同时经过认证和 Casbin 鉴权，公开接口必须显式保留。
2. 路由、权限点、Casbin 策略和前端权限码必须能一一追踪。
3. 数据规则必须在参数化 SQL 下生效，不允许拼接用户值。
4. 角色禁用后，动态菜单、按钮权限和 API 鉴权结果必须一致。
5. 每项只有在定向测试通过后才能标记为“已完成”。
