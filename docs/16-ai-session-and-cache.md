# AI 会话层：事件日志 · 主动压缩 · 前缀缓存（设计）

> 状态：**设计**（AI 模块第二阶段）。第一阶段「供应商 / 模型配置」是 `ai_provider` 单表（JSONB 主字段），
> 本文档描述其上的会话运行时 —— 目标一句话：**小窗口（100K 上下文）也能跑月级长会话，且省 token**。
> 机制来源：dsh（DeepSeek Harness）核心架构 + `billion-context` 插件的 ACP（Active Context Pruning）。
> 两者同源（dsh 的压缩机制 M1–M12 见 `docs/07-ai-module.md` §3），本文只记录**落到本仓库的形态**。

## 0. 三条机制，缺一不可

| 机制 | 解决什么 | 一句话 |
|---|---|---|
| append-only 事件日志 | 崩溃/重启后能接着上文；压缩永不丢原文 | 真源只有事件，历史是**投影** |
| 主动压缩（ACP） | 小窗口跑长会话、省 token | 模型自己决定压什么，压成**高保真摘要** |
| 前缀稳定纪律 | 缓存命中率（省 token 的大头在这里） | 稳定前缀字节不变，动态内容只追加尾部 |

省 token 的真相不是「压缩把字变少」，而是**压缩 + 前缀缓存**：压缩减少每轮要送的 token，
前缀稳定让 provider 端命中 prompt cache（同一前缀不重复计费）。两者叠加才有 5× 量级。

## 1. 事件日志是真源，历史是投影

- `ai_session`：会话身份（`id`、`external_id` 唯一、`user_id`、`kind`、`title`、`last_active_at`、`create_time`）。
- `ai_event`：**只追加**的类型化事件（`session_id`、`seq`、`kind`、`surface_op`、`payload`、`create_time`、`PRIMARY KEY(session_id, seq)`）。
- `surface_op` 只有两种：`append`，或 `{op:'replace', startSeq, endSeq}` —— 压缩不是删事件，是**追加一条置换事件**。
- 派生历史（surface）由事件投影得到：支持**增量**（从某个 seq 之后）与**分页**，不驻留全量序列。
- 失败尝试（网络错误、模型拒答）**不写入**派生历史（事件层可留诊断记录，但不进上下文）。

## 2. 压缩：模型驱动，剪枝优先

触发点有两个，都不许直接调 LLM 摘要：

1. **自动**：每步结束前计量 —— 越过「增长步长」（默认 ~50K token 的整数倍）先发一次**温和提醒**（nudge），
   是否压、压哪段仍由模型决定；只有超过预算阈值才进入强制流程。
2. **自救**：provider 明确报「上下文超窗」时，引擎自己抢救一次（有重试上限），否则这一步直接失败。

压缩流程（顺序铁律）：

1. **先剪枝**（零 LLM 调用）：工具结果截断、重复内容去重、早期轮次降级为大输出引用（正文外置）。
2. **重新计量**：剪枝后仍超限才进入摘要。
3. **摘要**：由模型自己写（把 `compress` 作为工具给它），范围是 `startSeq..endSeq`，产出**高保真摘要**——
   必须保留：文件路径与行号、已定决策与其理由、未完成事项、精确值（版本 / 阈值 / ID）。摘要入参必须**保持工具调用与结果的配对**，
   不许把一对拆到两个块里（拆了就出现「有调用没有结果」的历史，模型会当工具坏了）。
4. **落锁**：压缩在事件日志里写「开始 → 摘要 → 结束」三条；中途崩溃会留下**孤儿开始** —— 那是崩溃证据，不做自动清理。
5. 摘要成为派生历史里的一个 **checkpoint 节点**；原文保留在事件日志中，永不删除。

## 3. 缓存：前缀稳定纪律

- 每轮请求分成两段：**稳定前缀**（system prompt、工具 schema、固定指令）与**动态尾部**（本轮上下文）。
- 稳定前缀要求**字节级稳定**：顺序固定（升序拼接）、禁止每次请求重排 / 重写措辞 / 换分隔符。
- 动态上下文做「**变化才追加**」的持久快照：内容没变就不重写、不换位置，否则前缀缓存立刻失效。
- 任何会改动前缀的改动（改提示词、加工具、调顺序）都要评估**缓存命中损失**，在评审里写出来。
- **模型切换会作废整段前缀缓存**：同一会话中途换模型，provider 侧从头重新计费。会话层要把「模型切换」记成
  独立事件并在计量里单独归因 —— 否则这笔账会被误读成「缓存过期」。
- 计量真源只有一个（每会话一个 token 计量器），压缩前后都记实测值 —— 估算值不参与决策。

### 3.1 可观测口径（外部实证，直接当我们的验收基线）

`billion-context` 的 4.5 个月生产数据（174,327 次调用 / 18.76B 输入 token / 单会话 8,584–12,049 次调用的
马拉松 / 204,800 token 模型零窗口违规）给出三条可直接照抄的验收数字：

- **前缀缓存命中率**：健康会话 **95–97%**；跌破就查归因（上游 TTL 过期 → 模型切换 → 自己的 bug，按此顺序）。
- **压缩自身开销 ≤2%**：被折叠的那段必然要重写一次、miss 一次；长期超过 2% 说明压得太频繁或范围选得不好。
- **每次折叠算净收益**：省下的 token 必须覆盖「摘要调用 + 重写前缀」的成本 —— **短会话不值得压**。

所以计量器要能算出这三件事（命中率 / 压缩开销占比 / 每次折叠净收益），会话页把它们画出来。
没有这三个数，压缩策略只能靠感觉调。

## 4. 可恢复与可检索

- `decompress(blockId)`：把某个压缩块**逐字**恢复到上下文（块内原文来自事件日志，不是重新摘要）。
- `search_context`：在压缩块内做关键词检索，先搜后取，避免为了找一个路径把整块拉回来。
- 块是 checkpoint 节点：`decompress` 之后可以继续压缩同范围（产生新块），旧块仍可检索。

## 5. 前端（后台）

- 会话视图：消息流按投影渲染，压缩块显示为**可展开的折叠单元**（展开 = 摘要，再展开 = 原文）。
- 计量可视化：当前上下文占用 / 本轮增量 / 缓存命中情况（有则显示）。
- 权限点按资源逐个声明（`ai:provider_*` / `ai:session_*` 共 17 个，一码一路由，见 `internal/permission/codes.go` 的 ai 段）；会话数据是**用户自己的**，不跨用户可见。

## 6. 落地顺序（每步独立可验收）

1. `ai_session` + `ai_event` 两张表 + 事件写入与投影（含增量子查询与分页）→ 单测：投影与全量历史等价、崩溃重启后能接着跑。
2. **剪枝**（无 LLM）+ 计量器 → 单测：剪枝后 token 下降且工具配对完整。
3. `compress` / `decompress` / `search_context` 三个工具 + 压缩锁 → 单测：中途失败留孤儿开始、摘要保真字段断言（路径 / 决策 / 未完成项）。
4. 前缀稳定纪律：请求拼装器只允许「追加尾部」的操作，写一条静态断言（同一会话两次请求的稳定前缀必须逐字节一致）。
5. 会话视图前端（折叠块 + 计量展示）。

## 7. 明确不做

- 不在本仓库自建第二份「会话知识库」：语料与检索归属调用方，会话层只搬运（`docs/07-ai-module.md` §6 同口径）。
- 不做 provider 专有格式的持久化：事件日志与 provider 无关，换模型不迁移数据。
- 不自动删除任何事件：压缩只追加置换事件，删除入口不存在（与「发布产物不可变」同一条纪律）。

## 8. ADR（实现期落定）

**ADR-1：AI 配置与会话数据是全局对象，不带 `project_id`。**
供应商（`ai_provider`）与模型目录、以及会话（`ai_session` / `ai_event`）都是平台级对象，不参与多项目数据隔离（不受 215 的 RLS 约束）。理由：模型供应商是部署级基础设施，不属于任何项目。代价：同一部署内所有项目共用一份供应商配置与密钥。补偿控制三条——密钥只存密文（页面/接口只回 `HasAPIKey`）、改 API 地址即作废旧密钥并要求重填、出站请求过 SSRF 校验（只挡内网）。会话层与配置层**零耦合**：会话只存 `provider_key` + `model_id` 字符串，不建外键，因此换供应商或删除供应商都不会连带损坏历史会话。

**ADR-2：折叠的落定口径。**
`Fold` 在**一个事务**里连写三条事件：`compact_start`（记账）→ `compact_summary`（`surface_op=replace`，带 `replace_from_seq` / `replace_to_seq`，内容是摘要）→ `compact_end`（记账）；序号由事务内 `NextSeqTx` 分配，与事件写入、计量更新同事务提交。落定后 `context_tokens` 用投影的**绝对值重算**（不是增量加减），同时 `compact_count + 1`。投影的排序键必须是 `replace_from_seq` 而非事件 `seq`——折叠块的 `seq` 排在它盖掉的区间之后，用 `seq` 排序会把摘要推到上下文末尾。原文事件永远保留在日志里（可审计、可重放）。
