## 5. 文档 vs 代码的不一致（核对的主要产出）

1. **行号全部失效**：三份清单里记的文件行号在后续几批改动后**整体漂移**（4 份报告各自给出新旧对照）。
   引用清单时按**语义**定位，不要按行号跳转 —— 已写进 `AGENTS.md`。
2. **「未完成」被高估**：`02-L` P1-16 / P1-20 早就做完了却仍挂在待办上；
   P1-13「6 页无分页」实际 `administrators`/`datarules` 已接分页；P1-15「11 页 19 处」实际 4 页已补。
   方向是「做过的工作没被记账」，不是相反。
3. **部分判据本身站不住**：
   · **主会话的血的教训**：`grep -c 'class="pagination"'` 被当成「无分页」的判据 ——
     已接分页的 pages（products / orders / customers / returns / coupons）在同一判据下**同样是 0**
     （分页条在 `partials/pagination.html` 内部）。D3 的结论仍然成立（四页确实都没有），
     但不能靠那个计数支撑。
   · `02-O` 的 `?orderId=` 实测**无效**：id 是 `uint64`（`order_model.go:57`），报告用 UUID 形 URL
     恒解析为 0 → 那个 URL 下**永远无 badge**，无法区分「无注入」与「URL 走不通」。
   · `02-O` §0 速览表**不能当基线**：`customers.html` / `dashboard.html` 的 mtime 是 09-22 17:04/17:05，
     **早于** 17:32 的归档动作 —— 速览表的 `tables=0` 是更早一次实测的读数。
4. **实现 ≠ 建议**：`02-L` P0-4 的文档建议是「菜单改指 `/admin/products`」，实际实现是
   「302 + 引导文案 + 详情页入口」，菜单 path 至今仍是 `/admin/products/template`（`is_hidden=0`）。
   问题消除了，但不是文档写的那个解法。
5. **范围写小**：`02-L` P2-6 文档说 `.filter-bar` 两义并存「等 3 处」，实测**纯标题行 11 处 / 11 个模板**。
6. **成本被低估**：`02-L` P2-17 的死模板被 `TestProductPageWarehouseSelect` 间接依赖，
   文档评的「删一行 + 纯收益」不准确 —— 删它必须同批改测试断言。
7. **`02-P` §5 的 A 类清单有一处错**（我在那批里写「`orderenums.ErrInternal` 是裸归口 key」）：
   它是**中文常量**，三处真实症状只是脱页壳。已在 `02-P` 就地标注。
