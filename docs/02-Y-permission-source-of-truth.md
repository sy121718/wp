# 权限：路由即身份，权限码只是标签

> 状态：**方案（2026-10-07 定稿方向），全量未做**。判据已落地（`scripts/check-permission-gaps.sh` 已改为双向硬判据）。
> 本文取代早先的「权限点节点从路由推导」方案 —— 推导、别名表、命名规则都不需要，因为**权限的身份就是路径**。

## 1. 目标（三句话）

1. **鉴权只看路径**：`Enforce(用户, 请求路径, 方法)`。匹配得上就进，匹配不上就拒。
2. **权限码只是给人看的标签**：运营在授权界面上认得出「订单 / 优惠码 / 删除」，代码不拿它当身份。
3. **页面不参与权限判定**：路由过了就给页面；页面与按钮**渲染不渲染，看菜单**（菜单是运营能看懂的授权面）。
   · 注意：这条只说「权限点不按页面路径登记」，**不等于页面不需要鉴权** —— 页面 GET 必须逐路由
   挂 Casbin（借对应业务 API 的权限点），见 `02-Z-admin-menu-code-and-page-authz.md`。

## 2. 事实基线（实测，2026-10-07）

库里的一行策略**已经把三样东西放在一起**了：

```
id | ptype | v0(主体) | v1(路径)         | v2(方法) | v3(短码)
 1 |   p   |    1     | /api/page/list   |   GET    | page:list
 3 |   p   |    1     | /api/page/create |   POST   | page:create
```

| 项 | 实测 |
|---|---|
| Casbin 策略行 | 445 条，`(主体, 路径, 方法, 短码)` 同行 |
| 强制鉴权 | 已经是组中间件按路径：`builtin.CasbinMiddleware()` 用 `obj = 请求路径` |
| 页面组（`/admin/*`） | 组级**没有 Casbin**（Session + CSRF + 权限上下文）；但页面 GET **逐路由**挂 `CasbinMiddlewareForPath` —— 98 条里 28 条已挂、约 63 条未挂。见 `02-Z-admin-menu-code-and-page-authz.md` §2.1 |
| `PermSet`（模板里的按钮判断） | 由 `EffectivePermissionCodes` 从**库**里算出来，不来自代码 |
| 菜单 | `sys_menus` 绑 `PermissionCodes`，按用户有效权限码过滤后进侧栏 |
| 路由 | 318 条；权限点 321 条 |
| 代码侧声明 | `RouteGroup.GET/POST(path, perm, h)` 第二参 + `permission.Declare` 调用点 |

结论：**要改的不是判定链，而是「代码侧那份额外的声明」** —— 它是第三份真源（路由调用点、`sys_permission`、`codes.go` 常量），而前两份已经足够。

## 3. 要改的三处

| # | 现状 | 目标 |
|---|---|---|
| 1 | 每个路由手写一个权限点参数，装配期 upsert 进 `sys_permission` | **去掉这个参数**：权限点是数据，新增路由就加一行（迁移或后台界面） |
| 2 | `codes.go` 的 100+ 常量 + 注释里的路由绑定 | 常量**降级为显示标签**（保留给人看），不再承载「路由 ↔ 权限」的绑定 |
| 3 | 模板里 145 处 `isset(.PermSet["order:create"])` 决定按钮显隐 | 按「**看菜单**」驱动：按钮可见性与侧栏同源（菜单勾了就有） |

第 3 处是本次唯一有交互语义变化的地方：今天「菜单可见」与「按钮可用」是两套判定（菜单按 `PermissionCodes` 过滤、按钮按 `PermSet` 短码），
目标下两者同源 —— 运营勾一个菜单，页面与它上面的按钮一起出现，不再出现「页面进得去、按钮点了 403」。

## 4. 判据（已落地，两个方向都硬失败）

`bash scripts/check-permission-gaps.sh`：

- **方向 A**：每条 `/api/*` 路由都必须有权限点 —— 否则那条路由挂了 Casbin 却没有任何策略匹配，
  **含超管在内全员 403**（072/077/078/079/151 各踩过一次）。
- **方向 B**：每条权限点的 `api_path` 都必须存在于运行时路由表 —— 否则授权界面勾了它也没用
  （端点不存在），而它看起来完全正常，排查的人会先去怀疑角色与策略，方向全错。

判据比对的是**运行时装配出来的路由表**与 `sys_permission`，不是 grep 源码猜路径。

## 5. 迁移顺序（建议）

1. **清掉上面 7 条漂移**，让判据转绿（它是后续每一步的安全网）。
2. **去掉 `RouteGroup` 的权限点参数**（一个模块一个模块地改）。路由快照 `internal/routers/testdata/routes.snapshot`
   保证路径零漂移；`check-permission-gaps.sh` 的两个方向保证权限表跟着走。
3. **新增路由的登记流程换成数据**：加一行 `sys_permission`（迁移或后台界面）。漏了会被方向 A 当场拦住。
4. **按钮可见性改为菜单驱动**：模板里的 `PermSet[短码]` 逐步换成「菜单/路由」判定；菜单与按钮同源后，
   「页面进得去但按钮 403」这一类缺陷从设计上消失。
5. **`permission.X` 常量退役**：只留显示标签用途；`CasbinMiddlewareForPath` 直接用路径字符串（它本来就是路径）。

## 6. 边界（明确不做）

- **不做推导**：不需要从路径反推短码，也不需要别名表 —— 短码不是身份。
- **不给页面加 Casbin**：~~页面读由「登录 + 菜单可见性」控制，这是既有设计，也是本文目标 3。~~
  **此条已作废（2026-10-07 实测纠正）**：菜单隐藏不是访问控制，直接输 URL 就能绕过。
  页面 GET 必须逐路由挂 Casbin，且 enforce 的码要与该页菜单绑的码一致。
  详见 `02-Z-admin-menu-code-and-page-authz.md`（本文目标 3 的「页面不参与权限判定」只在
  「权限点不按页面路径登记」这个意义上成立）。
- **不动 `permission.Exempt`**：显式豁免仍然是看得见的选择。
- **不改 Casbin 策略数据结构**：`(主体, 路径, 方法, 短码)` 四列同行已经够用；短码列继续给 UI 显示。
