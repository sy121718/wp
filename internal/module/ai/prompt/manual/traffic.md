# 流量与内容

对应页面 `/admin/analytics`（访问统计）、`/admin/pages`（页面）、`/admin/articles`（文章）。
目前**没有流量/内容工具** —— 这些数字要请用户到对应页面看。

## 访问统计（analytics）

- 数据由**访客浏览器上报**（`POST /analytics/collect`）：它是全系统**唯一**由访问面写库的路径。
  后果是**数字偏小**：禁用 JS、被广告拦截、或页面没加载完就离开的访问都不计入。
  所以流量数字应当读成「下限」，不是「准确值」。
- 只存匿名派生值（IP / 会话的哈希），不存原始 IP。
- 明细按工程配置保留一段时间后清理，**汇总表保留**。问「上个月每天的明细」可能已经过期。

## 页面与文章

- 页面（`pages`）是手工建的；文章（`articles`）是内容模块的，两者都归属某个工程，
  都可能有多语言版本与发布状态。
- **发布不是即时的**：保存后要构建、发布、占 URL，还有回执确认。刚改完就刷新看不到变化，
  多半是这一串还没走完，而不是改动丢了。
- 页面有「草稿 / 已发布」两态；**改 URL 会重建产物**（canonical 烘在 HTML 字节里），
  所以改 URL 比改正文代价大。
- 「哪些页面受某次改动影响」是页面列表页上的只读信息（可见性计算），
  **不会自动重建** —— 需要人工确认后重建。

## 注意事项

- 流量数字与订单数字的时间对齐方式不同：订单按 **UTC 日界**，访问统计的「今天」
  取决于上报时刻。跨零点做对比时要说明。
- 问「哪个页面带来最多订单」——本系统**没有**这条链路（没有把页面访问与订单关联起来）。
  直说没有，不要用「浏览量高的页面」冒充转化。
