# 客户

对应页面 `/admin/customers`（列表 / 概览 / RFM 分析 / 群组留存）。目前**没有客户工具** ——
客户维度的数字要请用户去对应页面看，或由 `orders_summary` 的区间口径间接回答。

## 数据在哪

- 访客账号在 `users` 表；客户**不是**后台建出来的，是访客自己注册出来的。
- 「谁是客户」全系统按 `user_id` 判定（**不按邮箱**）：同一邮箱注册两次是两个账号。

## 口径（四个词，别混用）

- **新客**：**首次下单**落在区间内。不看注册时间 —— 注册了三个月、这周才第一次买的人，
  这周算新客。
- **回头客**：首单在区间**之前**，区间内又下了单。
- **复购**：区间内下了 **≥ 2 单**（不是历史累计）。默认门槛 2 单，页面可选 2 / 3 / 5 / 10。
- **留存**：该月**有下单**即算，**不要求连续活跃**。（这一点与很多分析工具不同：
  那些工具算「连续 N 个月都买」，本系统不这么算。）
- **恒等式**：新客 + 回头客 = 区间下单客户数。答不满足这个等式的数字时先自查。

## RFM 分段

- 三个维度各打 1–5 分，总分 3–15：`≥12` 高价值（vip）、`≥8` 潜力（potential）、其余一般（low_value）。
- R 看**全历史**最后一次下单距今天数；F 与 M 只看所选窗口内。
- **分数是相对的**（金额按本店数据的五分位划分，不是固定阈值）—— 换个时间窗口，
  同一个人可能从 vip 掉到 potential。回答时必须说明这一点，否则「高价值客户」会被当成绝对等级。

## 群组留存（Cohort）

- 按**首单所在自然月**分群，矩阵里第 N 列 = 该群在第 N 个月**有购买**的人数。
- 分母是**本群人数**（不是全体客户）。
- 早的群列数多、晚的群列数少，这不是数据缺失 —— 后面的月份还没到。

## 注意事项

- 客户列表的筛选是**多个维度求交**（消费分段 × 复购次数 × RFM × 会员等级 × 状态），
  用户描述「既…又…」时把条件都带上。
- 客户概览页的三个数字与客户列表按同条件筛出的条数**必须一致**（这是项目的对账闸门）。
  答出来的数若对不上，先怀疑区间或工程没对齐，而不是数据错了。
