# templates — 前端层

## 职责

前端的全部：后台页面、工作台外壳、运行时片段、访客账号页、公共 partial、静态资产（CSS / JS / vendor）。结构、样式、取词、徽标分档、空态、分页与时间/金额显示的**唯一去处**。

本目录同时承载渲染引擎的 Go 侧能力（Jet 渲染器、无请求上下文的纯函数、分页派生、嵌入加载）。

分页的算力切分是：**事实**（总数 / 当前页 / 每页条数）由业务层给；**页码窗口与取址**在 `pkg/pagination`（有主张的显示策略，带 oracle 对照测试）；**区间句、信息行、按钮态**在 `pager.go` 与 partial。模板只 range 槽位，不自己算窗口、不比较相邻页码画省略号。

## 边界

- **是前端层，不是后端**：不能出现业务规则的第二份实现，不能做金额求和或库存合计，不能有业务 Go 代码。
- **模板自己取词与分档**：徽标、空态、状态文案、选中态由模板判断；业务层只交事实。
- **通用 UI 形态只在这里有一份实现**：空态、徽标、批量条、日期筛选、抽屉、下拉一律走 partial 或 `static/js/ui/`；`pkg/` 不长出给页面用的助手包（`pagination` 是白名单内唯一的显示策略包，理由见 `pkg/pagination` 文件头）。
- **一份源两个出口**：运行时经 `/static` 提供，构建期部分资产内联进产物；不维持两套源。
- 访客账号页刻意不引后台主题与控件基座，要求无脚本可用。

## 关键约束

模板的契约（取词写法、缺键、include 传参、写操作走统一 JS 基座、多端与动效要求）见 `internal/templates/CLAUDE.md`，本文件不复述。
